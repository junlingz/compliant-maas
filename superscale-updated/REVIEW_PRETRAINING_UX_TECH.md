## P1

### P1-1 成功提示与真实页面状态不一致，多项核心操作属于“提示已完成、实际未执行”

**复现路径**

1. 进入“文-图生成训练框架 → 超参数配置与调优”。
2. 记录学习率、批次/梯度累积、轮次、精度值。
3. 点击任一非当前预设方案。
4. Toast 提示“参数已自动填充”，但四个字段值完全未变化。

另可复现：

- “拓扑与资源感知的分布式训练 → 分布式训练核心功能 → 智能生成拓扑”：提示已重新生成，拓扑 DOM 与效率 `91.6%` 均未变化。
- “推理引擎 → 模型推理部署”：搜索 `不存在模型XYZ` 后点击“组合筛选”，仍显示原来的 3 张模型卡。
- “模型测评框架 → 测评数据集支持”：从“公开数据集”切到“团队共享”，数据卡内容完全相同。
- “技术文档中心”：搜索 `绝对不存在的搜索词XYZ`，列表不变，也没有高亮，却提示“找到 12 篇”“关键词已高亮”。
- “多任务对比”“交付步骤”“服务监控”“审计日志”“编排历史”“分类管理”等入口均只显示 Toast，没有打开相应视图、抽屉或结果区。

**证据**

- 操作消息集中在 `index.html:329-348`，命中消息后直接 `toast(...)`，后续状态更新分支不会执行。
- 预设前后字段实测均为 `["1e-5","8 / 4","20","BF16"]`。
- 拓扑操作前后 `#topology.innerHTML` 完全一致，`#efficiency` 均为 `91.6%`。
- 模型筛选前后 `.model-card` 数量均为 3。
- 数据集标签切换前后 `.dataset-grid.innerText` 完全一致。
- 文档搜索前后 `.doc-grid.innerText` 完全一致。

**整改建议**

- 为每类操作定义最小但真实的状态模型：筛选必须改变列表或空状态；预设必须回填字段；模板保存/删除必须更新模板列表；拓扑生成必须改变节点或效率；“打开/查看”必须打开抽屉、弹窗或结果面板。
- Toast 只用于总结已经发生的变化，不能替代变化本身。
- 将这些状态断言补入浏览器测试，不只检查 Toast 是否出现。

### P1-2 配置导出和任务提交不读取用户输入，无法形成“配置—校验—提交—回显”闭环

**复现路径**

1. 进入“自回归预训练框架 → 模型训练核心功能”。
2. 将学习率改为 `0.0009`、批次改为 `32`、精度改为 `FP16`。
3. 点击“导出配置”并查看下载的 JSON。
4. 文件仍固定为 `learning_rate: 0.00002`、`batch_size: 16`、`precision: "BF16"`。
5. 再将学习率设为空值或越界值，点击“校验并提交任务”，仍然得到“配置校验通过”，任务立即进入队列。

**证据**

- 配置字段位于 `index.html:163-170`。
- `startTask()` 在 `index.html:323-326` 直接创建任务，没有读取控件、调用 `checkValidity()` 或输出字段级错误。
- `exportConfig` 在 `index.html:355` 下载硬编码对象，不读取当前页面输入。
- 上传校验在 `index.html:389` 只判断文件扩展名，却提示已经完成“编码、Schema/配对关系与完整性校验”。

**整改建议**

- 建立当前页面配置对象，所有输入 `change/input` 时同步状态；导出、保存模板、提交任务均从同一对象读取。
- 提交前执行必填、类型、范围、依赖与资源校验；失败时在字段旁显示错误并聚焦第一个错误，不创建任务。
- 任务详情抽屉应回显本次真实配置。
- 上传至少按上下文区分允许格式，并对原型可验证的内容做真实解析；无法解析的深层校验应明确标注为“模拟”，不要宣称已完成。

### P1-3 多个语义不同的能力页渲染为完全相同的工作台，缺少能力区分度

**复现路径**

依次切换以下标签，除标题、说明和右侧条款卡外，主工作区结构与内容完全相同：

- 自回归：“模型训练核心功能”与“自动化模型评估”。
- 序列到序列：“模型训练核心功能”与“自动化模型评估”。
- 分布式训练：“分布式训练核心功能”与“多范式并行训练支持”。
- 有监督微调：“分布式微调支持”与“GPU资源调度”。
- 有监督微调：“框架扩展能力”与“微调框架扩展”。
- 自回归“训练过程可视化”、文-图“训练监控与日志管理”、测评“自动化报告与可视化”也共享同一指标、同一图表、同一日志。

**证据**

- `patternFor()` 在 `index.html:125-142` 仅按标题正则选择少量通用 renderer，未匹配的能力全部落入 `config`。
- 主工作区去掉标题块后做 DOM SHA-1，得到完全相同的分组：
  - `autoregressive/模型训练核心功能` = `autoregressive/自动化模型评估`
  - `seq2seq/模型训练核心功能` = `seq2seq/自动化模型评估`
  - `distributed/分布式训练核心功能` = `distributed/多范式并行训练支持` = `finetune/分布式微调支持` = `finetune/GPU资源调度`
  - `finetune/框架扩展能力` = `finetune/微调框架扩展`
- 自动化评估页展示的是训练架构、学习率、批次、轮次等训练配置，而不是评估指标、评估数据、样本对照与报告。

**整改建议**

- 保留可复用组件，但为不同能力增加专属配置和结果区。
- 自动评估应至少提供指标选择、评估数据、频率、样本“输入/生成/标签”、结果表和报告导出。
- 多范式并行应提供数据/模型/流水线/张量并行选择及对应动态参数和配置预览。
- GPU 调度应提供单卡利用率、显存、温度、功耗、通信带宽和非最优路径告警，而不是复用集群接入表单。
- 监控、报告、测评可复用图表组件，但指标名称、操作、数据结构与结果必须与能力语义一致。

### P1-4 弹窗、抽屉和总览入口不具备完整键盘可操作性

**复现路径**

1. 用键盘聚焦“创建任务”并激活。
2. 弹窗打开后，焦点仍停留在弹窗后方的“创建任务”按钮。
3. 按 `Escape`，弹窗不关闭。
4. 继续按 `Tab`，焦点没有被限制在弹窗内。
5. 打开任一“标书能力核验”抽屉，表现相同。
6. 在平台总览使用 `Tab`：6 个业务流程卡和 8 个模块卡均无法聚焦，也无法用 Enter/Space 激活。

**证据**

- 实测弹窗打开后 `document.activeElement` 仍为背景“＋ 创建任务”按钮。
- 按 Escape 后 `#modalBackdrop.open === true`；抽屉同样保持打开。
- `#modal` / `#drawer` 没有 `role="dialog"`、`aria-modal="true"` 或标题关联，见 `index.html:312-320`。
- 总览入口使用带 `data-page` / `data-process` 的 `<article>`，无 `tabindex` 和交互角色；点击委托位于 `index.html:375-380`。

**整改建议**

- 打开弹层时保存触发元素、将焦点移入、设置 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`，实现焦点循环；关闭后将焦点归还触发元素。
- 支持 Escape 关闭弹窗、抽屉和移动导航。
- 将模块卡、流程卡改为原生 `<button>` / `<a>`，或补齐 `tabindex="0"`、语义角色和 Enter/Space 键处理。
- 背景在弹层打开时应使用 `inert` 或等效方案，避免屏幕阅读器和键盘访问背景控件。

## P2

### P2-1 表单可见标签未与控件建立程序化关联

**复现路径**

1. 进入任一训练配置页。
2. 使用屏幕阅读器或检查可访问性树。
3. “训练架构 / 算法”“数据集”“学习率”“批次大小”“训练轮次”等标签没有成为对应控件的可访问名称。

**证据**

- 训练配置页实测有 8 个可见输入/选择控件缺少 `aria-label`、`aria-labelledby`、外包裹 `<label>` 或 `label[for]`。
- 示例源码见 `index.html:163-170`；其他 renderer 也大量采用相同的相邻标签结构。

**整改建议**

- 为每个控件提供唯一 `id`，并使用 `<label for="...">`；动态页面保持 id 唯一。
- 搜索框、表格筛选和文件上传也应提供可访问名称，而不是只依赖 placeholder。

### P2-2 移动导航没有遮罩、焦点管理和明确的关闭路径

**复现路径**

1. 在 390px 宽度点击左上角菜单。
2. 侧栏覆盖页面，但右侧背景仍可见、可点击、可被键盘聚焦。
3. 按 Escape 无法关闭；页面中也没有独立的“关闭导航”按钮。

**证据**

- 移动样式只切换 `.sidebar.open` 的 transform，见 `index.html` 的 `@media(max-width:760px)`。
- `menu` 操作只执行 `classList.toggle('open')`，见 `index.html:353`。

**整改建议**

- 增加半透明 scrim，点击 scrim 或按 Escape 关闭。
- 打开后将焦点移到首个导航项并限制在导航内，关闭后回到菜单按钮。
- 菜单按钮同步 `aria-expanded`、`aria-controls`，侧栏提供明确关闭按钮。

### P2-3 通用文件选择器无法表达不同上传场景，且部分必要格式不可选择

**复现路径**

1. 进入文-图训练的数据上传、分布式训练的“.py 分析”或模型导入。
2. 所有上传入口最终共用同一个隐藏文件控件。
3. 图片、图文数据压缩包等文-图场景文件无法选择；“.py 分析”按钮甚至不打开文件选择器，只显示成功 Toast。

**证据**

- 全局文件控件 `accept=".json,.jsonl,.csv,.txt,.yaml,.yml,.py,.pth,.safetensors"`，见 `index.html:65`。
- `analyzeModel` 在消息映射中直接成功，见 `index.html:334`。
- 文件校验不读取 `state.fileContext`，所有场景均使用同一扩展名规则，见 `index.html:389`。

**整改建议**

- 根据 `data-context` 动态设置 `accept`、提示、示例和校验器。
- 文-图数据支持原型约定的 ZIP/目录清单/图像格式；并行分析真实接收 `.py`；权重导入要求权重与配置的组合校验。
- 上传结果显示文件名、大小、解析进度、成功统计和可恢复的错误明细。

### P2-4 数据导出内容与按钮语义不完全一致

**复现路径**

- 在“统一任务中心”点击“导出任务清单”，下载文件名和内容仍是固定 `task-logs.txt`，并非当前任务表。
- 点击“批量测试并导出样例”，没有触发下载，只显示“样例已导出”Toast。
- 点击“下载完整白皮书”，下载的是很短的 TXT，不是界面所表达的完整白皮书/PDF。

**证据**

- `exportLogs`、`downloadWhitepaper` 与 `batchTest` 分别见 `index.html:345-359`。

**整改建议**

- 每个下载按钮生成与当前页面、筛选条件和按钮名称一致的文件。
- 原型可使用 CSV/JSON/HTML 代替 PDF，但按钮文案和文件格式必须一致；若为演示文件，应明确标注。
- 为下载动作增加自动化测试，断言文件名、MIME、核心字段和当前状态一致。

### P2-5 信息密度略低于参考后台，部分辅助文字过小

**复现路径**

1. 在 1440px 桌面端查看总览和能力核验区。
2. 页面大量使用 18px 圆角卡片和卡片套卡片，主内容的可扫描密度低于参考截图的紧凑表格式后台。
3. 条款号、标签、图例和流程描述大量使用 10–11px 字号，长时间阅读较吃力。

**证据**

- `--radius:18px`；`.req .clause`、`.req-items button`、`.chip`、`.legend`、`.process-step p` 为 10px 或 11px。
- 总览桌面截图的框架卡、统计卡、流程卡均占据较大垂直空间。

**整改建议**

- 将主要容器圆角统一到 8–12px，减少嵌套卡片和阴影，用分区、分隔线和表格增强后台工作台密度。
- 正文和可交互标签尽量不低于 12px，关键辅助信息建议 12–13px。
- 保留浅蓝企业后台配色；该方向与用户截图一致，不需要改成营销页风格。

### P2-6 实时日志定时追加无上限，长时间停留会持续增长 DOM

**复现路径**

1. 打开任一训练监控页面并持续停留。
2. 每 3 秒向 `#liveLog` 追加一行，旧日志从不裁剪。

**证据**

- `setInterval` 在 `index.html:393` 使用 `innerHTML +=` 持续追加，无最大条数、暂停或页面可见性判断。

**整改建议**

- 使用固定长度环形缓冲区（如最多 200 行），通过节点追加而非反复重写整个 `innerHTML`。
- 页面不可见或离开监控页时暂停更新，提供“暂停滚动/清空/下载”。

### P2-1 表单可见标签未与控件建立程序化关联

状态：**仍开放**

大部分表单已由 `hydrateAccessibility()` 自动建立 `label[for]` 或补充 `aria-label`，但遍历全部 39 个能力页后仍发现 4 个无可访问名称的控件：

| 页面 | 能力 | 控件 |
|---|---|---|
| 自回归预训练框架 | 模型训练核心功能 | `#expertCount` |
| 有监督的微调框架 | 模型微调核心功能 | `#loraRank` |
| 有监督的微调框架 | 模型微调核心功能 | `#loraAlpha` |
| 模型测评框架 | 模型对比分析 | 场景名称文本框（无 id） |

复现方法：

1. 打开上述能力页。
2. 在可访问性树中检查控件名称，或检查控件是否具有 `aria-label`、`aria-labelledby`、包裹式 `<label>`、`label[for]`。
3. 四个控件均不满足任一条件。

原因：

- `#expertCount`、`#loraRank`、`#loraAlpha` 位于 `.summary`，不在 `hydrateAccessibility()` 遍历的 `.field` 中。
- 模型对比的同一 `.field` 内先有一个多选框，再有“场景名称”标签和第二个输入框；自动关联只处理第一个控件。

源码证据：`index.html:192`、`index.html:209`、`index.html:326`、`index.html:386-390`。

整改建议：

- 为前三个输入分别增加显式 `<label for="expertCount">`、`<label for="loraRank">`、`<label for="loraAlpha">`，或等价 `aria-label`。
- 为场景名称输入增加唯一 id，并让“场景名称”使用匹配的 `for`。
- 将 39 页“无可访问名称控件数必须为 0”加入自动化测试。

### P2-2 移动导航没有完整遮罩、焦点管理和关闭状态

状态：**仍开放**

已修复部分：

- 390px 下打开菜单会显示半透明 scrim。
- 打开后焦点进入首个导航项。
- 点击 scrim、关闭按钮或 Escape 可以关闭侧栏，焦点返回菜单按钮。

仍存在的问题：

1. 关闭后菜单按钮的 `aria-expanded` 仍为 `"true"`，没有同步回 `"false"`。
2. 打开侧栏后，将焦点放在最后一个导航项并按 Tab，焦点会离开侧栏进入背景菜单按钮，导航没有焦点循环或背景 `inert`。

实测状态：

- 打开：侧栏 `open=true`、scrim `open=true`、`aria-expanded="true"`。
- 点击 scrim 关闭：侧栏关闭、焦点返回菜单按钮，但 `aria-expanded` 仍为 `"true"`。
- 最后一个导航项按 Tab：`document.activeElement` 位于侧栏外。
- Escape 关闭后：`aria-expanded` 仍为 `"true"`。

原因证据：

- `menu` 分支在打开时设置 `aria-expanded`，但 `closeMenu` 只移除 class 和恢复焦点，没有设置为 false，见 `index.html:437-438`。
- 移动导航没有与弹窗相同的 Tab 焦点循环或 `inert` 背景处理。

整改建议：

- 在所有关闭路径统一执行 `menuButton.setAttribute('aria-expanded','false')`。
- 打开移动导航时将主内容设为 `inert`，或为侧栏实现首尾焦点循环；关闭时恢复。
- 增加自动化断言：打开/关闭 ARIA 状态、首尾 Tab、scrim、Escape 和焦点归还。
